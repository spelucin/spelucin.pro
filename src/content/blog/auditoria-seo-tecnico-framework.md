Una auditoría SEO técnica no es una lista de errores. Es un diagnóstico con prioridades. Cada hallazgo debe tener un nivel de impacto y una recomendación clara.

## Fase 1: Acceso y contexto

Antes de crawlear, necesito entender:

- Cuántos SKUs tiene la tienda
- Cuánto tráfico orgánico tiene actualmente
- Qué cambios recientes se hicieron (tema, migración, agencia)
- Cuáles son las páginas que más revenue generan

Sin este contexto, cualquier auditoría es una lista genérica.

## Fase 2: Crawl técnico

El crawl es donde empieza el trabajo real:

- **Indexación** — ¿cuántas páginas indexa Google vs. cuántas existen?
- **Crawl budget** — ¿Google está rastreando las páginas correctas?
- **Duplicados** — ¿hay contenido duplicado que diluye la autoridad?
- **Broken links** — ¿hay enlaces rotos que bloquean el crawl?
- **Redirects** — ¿las redirecciones están bien configuradas?

## Fase 3: Core Web Vitals

Los Core Web Vitals son métricas reales de usuario:

- **LCP** — ¿carga rápido el contenido principal?
- **CLS** — ¿el layout se mueve inesperadamente?
- **INP** — ¿el sitio responde rápido a interacciones?

En Shopify, los problemas más comunes vienen del tema, las apps y las imágenes sin optimizar.

## Fase 4: Schema markup

El schema markup le dice a Google qué es cada página:

- Product schema con Offers
- Review schema
- BreadcrumbList
- Organization
- FAQPage (si hay FAQ)

En Shopify, el schema viene parcialmente configurado por el tema. Pero casi siempre hay errores o campos faltantes.

## Fase 5: Arquitectura y enlazado

- ¿La estructura de URLs es semántica?
- ¿Las páginas importantes están enlazadas desde la navegación?
- ¿Los filtros generan URLs duplicadas?
- ¿Hay páginas huérfanas sin enlaces internos?

## El entregable

Cada auditoría termina con un documento que tiene:

- Hallazgos con evidencia
- Nivel de impacto (alto, medio, bajo)
- Nivel de dificultad de implementación
- Hoja de ruta priorizada

No es un PDF automatizado. Es un plan de acción que tu equipo puede implementar.
